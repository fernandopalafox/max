## Subspace Alignment Test

The LoRA-XS initialization scheme (Observation 3.1) assumes that the dominant singular vectors of a fully trained weight matrix $W_{final}$ align with those of the accumulated raw pre-training gradient $G_{sum\_unscaled}$. This is the theoretical justification for initializing LoRA-XS adapter directions from the pre-trained weight's singular vectors. We run a controlled experiment to test whether this assumption holds empirically, and to understand how much optimizer dynamics (Adam momentum/variance scaling) contribute to or destroy this alignment.

We run 4 seeds of vanilla TDMPC2 pretraining (dense dynamics, 1M steps) on cheetah, accumulating gradient sums throughout training. For each Dense kernel in the dynamics MLP at each training step $t$, we add the raw backprop gradient to $G_{sum\_unscaled}$ and the Adam-scaled update (from `wm_optimizer.update`) to $G_{sum\_scaled}$. After training, we compute truncated SVD (r=16) on $W_{final}$, $\Delta W = W_{final} - W_{initial}$, $G_{sum\_unscaled}$, and $G_{sum\_scaled}$, then measure mean cosine of principal angles between all four pairs.

**Code added:**
- `max/trainers_grad_capture.py` — new trainer (`init_grad_capture_trainer`) with `GradCaptureTrainState` holding running `g_sum_unscaled` and `g_sum_scaled` accumulators for each Dense kernel; otherwise identical to `init_tdmpc2_trainer`
- `scripts/train_grad_capture.py` — training script that uses the grad-capture trainer and saves `grad_capture.pkl` (containing `w_initial`, `w_final`, `g_sum_unscaled`, `g_sum_scaled`) after training
- `scripts/analyze_subspace.py` — loads saved data per seed, computes SVD subspace alignment for all four pairs per layer, aggregates across seeds
- `configs/pretrain_grad_capture_tdmpc2.json` — same as `pretrain_dense_tdmpc2.json`, W&B project `subspace_alignment`

**Launch (4 GPUs in parallel):**

```bash
GPUS=(0 1 2 3)
RUNS=(1 2 3 4)
for i in 0 1 2 3; do
    conda run -n max python scripts/train_grad_capture.py \
        --config configs/pretrain_grad_capture_tdmpc2.json \
        --save-dir data/models/cheetah/grad_capture/run_${RUNS[$i]} \
        --run-name subspace_align_r${RUNS[$i]} \
        --seed ${RUNS[$i]} \
        --gpu ${GPUS[$i]} &
done
wait
```

**Analysis:**

```bash
conda run -n max python scripts/analyze_subspace.py \
    --dirs data/models/cheetah/grad_capture/run_{1,2,3,4} \
    --rank 16
```

W&B project: `subspace_alignment`, run names `subspace_align_r1` through `subspace_align_r4`.

Save dirs: `data/models/cheetah/grad_capture/run_{1..4}/`.

## Results

4 seeds, r=16 singular vectors, metric = mean cosine of principal angles ∈ [0, 1].

| Layer   | U_Wfinal vs U_Gunscaled (Obs 3.1) | U_deltaW vs U_Gunscaled | U_deltaW vs U_Gscaled | U_Wfinal vs U_deltaW |
|---------|-----------------------------------|-------------------------|-----------------------|----------------------|
| Dense_0 | 0.5885 ± 0.0146                   | 0.5932 ± 0.0183         | 1.0000 ± 0.0000       | 0.9865 ± 0.0022      |
| Dense_1 | 0.5185 ± 0.0128                   | 0.5163 ± 0.0151         | 1.0000 ± 0.0000       | 0.9810 ± 0.0181      |
| Dense_2 | 0.4555 ± 0.0125                   | 0.4539 ± 0.0133         | 1.0000 ± 0.0000       | 0.9910 ± 0.0024      |
| Dense_3 | 0.6559 ± 0.0058                   | 0.6575 ± 0.0073         | 1.0000 ± 0.0000       | 0.9606 ± 0.0051      |

**Takeaways:**

U_Wfinal vs U_Gunscaled (Obs 3.1): alignment is ~0.46–0.66 across layers, far below 1.0. Observation 3.1's assumption that the final weight matrix's dominant singular vectors align with the accumulated raw gradients is empirically false. The raw gradient sum is only a moderate predictor of the final weight structure.

U_deltaW vs U_Gunscaled: nearly identical values to U_Wfinal vs U_Gunscaled (~0.45–0.66). This means the raw gradient sum predicts the actual weight trajectory (delta_W) about as well as it predicts W_final — moderate but not strong alignment. The similar values for both metrics also show that W_initial contributes little to the dominant subspace of W_final (confirmed below).

U_deltaW vs U_Gscaled: exactly 1.0 for all layers and seeds. This is expected by construction — since G_sum_scaled is the accumulated optimizer updates (the wm_updates directly), and delta_W = W_final − W_initial = the sum of those same updates, these two matrices are literally identical. The perfect alignment is a sanity check that gradient accumulation is correct, not a substantive finding about optimizer geometry.

U_Wfinal vs U_deltaW: very high alignment (~0.96–0.99). Since W_final = W_initial + delta_W, this tells us delta_W dominates the final weight structure — initialization noise does not meaningfully corrupt the dominant subspace of W_final. This is consistent with standard practice of initializing near zero (small init std).

**Bottom line:** Observation 3.1 is empirically false. The raw gradient sum explains only ~50% of the dominant subspace of the final weights. Adam's momentum and variance scaling do not destroy this relationship further (the 1.0 U_deltaW vs U_Gscaled is trivial by construction), but the more fundamental issue is that 1M steps of training with temporal correlations, changing loss landscapes, and gradient clipping produces a final weight matrix whose dominant directions are only loosely predicted by the raw gradient accumulation. LoRA-XS initialization from W_final singular vectors is therefore not justified by gradient signal alignment alone.

## Subspace Alignment — Last 100k Steps Only

Follow-up: the LoRA-XS paper suggests gradients stabilize toward the end of training, so the gradient subspace late in training might align better with W_final than the full 1M-step sum. Re-running the same 4 seeds but resetting the gradient accumulators at step 900k, so `g_sum_unscaled` and `g_sum_scaled` only contain the final 100k steps.

Added `--capture-last-steps N` argument to `scripts/train_grad_capture.py`. At `chunk_idx == num_chunks - N/chunk_size`, the accumulators are zeroed in Python between scan chunks (no JAX state change needed at JIT boundaries).

**Launch:**

```bash
GPUS=(0 1 2 3)
RUNS=(1 2 3 4)
for i in 0 1 2 3; do
    conda run -n max python scripts/train_grad_capture.py \
        --config pretrain_grad_capture_tdmpc2.json \
        --save-dir data/models/cheetah/grad_capture_last/run_${RUNS[$i]} \
        --run-name subspace_align_last100k_r${RUNS[$i]} \
        --seed ${RUNS[$i]} \
        --gpu ${GPUS[$i]} \
        --capture-last-steps 100000 &
done
wait
```

**Analysis (once complete):**

```bash
conda run -n max python scripts/analyze_subspace.py \
    --dirs data/models/cheetah/grad_capture_last/run_{1,2,3,4} \
    --rank 16
```

W&B project: `subspace_alignment`, run names `subspace_align_last100k_r1` through `subspace_align_last100k_r4`.

Save dirs: `data/models/cheetah/grad_capture_last/run_{1..4}/`.

## Results — Last 100k Steps

4 seeds, r=16 singular vectors, metric = mean cosine of principal angles ∈ [0, 1].

| Layer   | U_Wfinal vs U_Gunscaled (Obs 3.1) | U_deltaW vs U_Gunscaled | U_deltaW vs U_Gscaled | U_Wfinal vs U_deltaW |
|---------|-----------------------------------|-------------------------|-----------------------|----------------------|
| Dense_0 | 0.5019 ± 0.0111                   | 0.4930 ± 0.0130         | 0.8118 ± 0.0306       | 0.9865 ± 0.0022      |
| Dense_1 | 0.3412 ± 0.0100                   | 0.3399 ± 0.0094         | 0.3382 ± 0.0169       | 0.9810 ± 0.0181      |
| Dense_2 | 0.3178 ± 0.0156                   | 0.3153 ± 0.0158         | 0.4501 ± 0.0183       | 0.9910 ± 0.0024      |
| Dense_3 | 0.5869 ± 0.0115                   | 0.5702 ± 0.0068         | 0.7152 ± 0.0130       | 0.9606 ± 0.0051      |

**Takeaways:**

U_Wfinal vs U_Gunscaled (Obs 3.1): alignment is ~0.32–0.59, which is *worse* than the full 1M-step run (~0.46–0.66). Restricting to the last 100k gradient steps does not improve alignment with W_final — it degrades it. This directly contradicts the LoRA-XS paper's claim that late-training gradients better predict the final weight structure.

U_deltaW vs U_Gunscaled: again nearly identical to U_Wfinal vs U_Gunscaled (~0.32–0.57), consistent with W_initial contributing little to the dominant subspace of W_final.

U_deltaW vs U_Gscaled: now ranges 0.34–0.81 (not 1.0 as in the full-run experiment). This is expected: G_sum_scaled here is only the last 100k optimizer updates, while delta_W = W_final − W_initial reflects all 1M steps. The non-trivial alignment (~0.34–0.81) shows late-training updates partially (but far from perfectly) explain the total weight trajectory. The higher values for Dense_0 and Dense_3 (~0.81 and ~0.72) suggest the final 10% of training has more influence on those layers' dominant directions.

U_Wfinal vs U_deltaW: unchanged at ~0.96–0.99, as expected — the full training trajectory still dominates W_final's subspace regardless of which gradient window we examine.

## Subspace Alignment — First 100k Steps Only

We've seen that the full 1M-step gradient sum gives ~0.46–0.66 alignment with W_final, and the last-100k sum gives ~0.32–0.59 (worse). The full sum mixes early and late gradient signal, which could blur a stronger pattern at either end. This experiment isolates the first 100k steps to complete the picture: does gradient-W_final alignment improve or degrade from start to end of training?

Since we only need the first 100k steps, runs stop early (no need to train to 1M). W_final is taken from the existing full-run pkl files (same seeds), using the new `--wfinal-dirs` argument in `analyze_subspace.py`.

**Launch (4 GPUs in parallel, stop at 100k steps):**

```bash
GPUS=(0 1 2 3)
RUNS=(1 2 3 4)
for i in 0 1 2 3; do
    conda run -n max python scripts/train_grad_capture.py \
        --config pretrain_grad_capture_tdmpc2.json \
        --save-dir data/models/cheetah/grad_capture_first/run_${RUNS[$i]} \
        --run-name subspace_align_first100k_r${RUNS[$i]} \
        --seed ${RUNS[$i]} \
        --gpu ${GPUS[$i]} \
        --max-steps 100000 &
done
wait
```

**Analysis:**

```bash
conda run -n max python scripts/analyze_subspace.py \
    --dirs data/models/cheetah/grad_capture_first/run_{1,2,3,4} \
    --wfinal-dirs data/models/cheetah/grad_capture/run_{1,2,3,4} \
    --rank 16
```

W&B project: `subspace_alignment`, run names `subspace_align_first100k_r1` through `subspace_align_first100k_r4`.

Save dirs: `data/models/cheetah/grad_capture_first/run_{1..4}/`.

**Takeaways:**

Comparing U_Wfinal vs U_Gunscaled across all three gradient windows:

| Layer   | Full 1M | First 100k | Last 100k |
|---------|---------|------------|-----------|
| Dense_0 | 0.5885  | 0.4851     | 0.5019    |
| Dense_1 | 0.5185  | 0.3890     | 0.3412    |
| Dense_2 | 0.4555  | 0.3608     | 0.3178    |
| Dense_3 | 0.6559  | 0.4905     | 0.5869    |

The full 1M-step gradient sum produces the highest alignment with W_final across all layers — not early gradients, not late gradients. Neither endpoint is a better predictor than the aggregate. The first 100k beats the last 100k on Dense_1 and Dense_2, but the difference is small and both are well below the full-sum values.

**Bottom line across all three experiments:** Gradient-W_final alignment is weak at every window of training (~0.32–0.66) and no single period explains the final weight structure. The full sum edges out both endpoints, suggesting diverse gradient directions throughout training collectively shape W_final better than either the beginning or end alone. Observation 3.1 is empirically unsupported regardless of which gradient window is used.

## LoRA-XS with Scaled-Gradient SVD Adaptation

Since Observation 3.1 is false (weights are a poor proxy for gradient subspace), we skip the proxy and initialize LoRA-XS A/B directly from SVD of the **average Adam-scaled gradient** (g_sum_scaled from the grad_capture runs). We use the scaled gradient (optimizer updates) rather than the raw gradient because the scaled updates are what was actually applied to the weights — `sum(g_sum_scaled) = delta_W` exactly. Backbone frozen, fresh R, same tdmpc2frozen trainer as the `loraxs_from_dense` baseline.

**Code added:**
- `max/dynamics_gradsvd.py` — `init_gradsvd_lora_xs_dynamics(key, config, pretrained, grad_avg)`: self-contained LoRA-XS init using SVD of `grad_avg["Dense_i"]` for A/B
- `scripts/train_gradsvd.py` — adaptation training script; loads `g_sum_scaled` from `grad_capture_path` config key and passes to `init_gradsvd_lora_xs_dynamics`
- `configs/adapt_full_with_loraxs_gradsvd_pt.json` — adaptation config, W&B group `loraxs_gradsvd`, pretrained from `grad_capture/run_1`

**Launch (4 GPUs in parallel):**

```bash
GPUS=(0 1 2 3)
SEEDS=(1 2 3 4)
for i in 0 1 2 3; do
    conda run -n max python scripts/train_gradsvd.py \
        --config adapt_full_with_loraxs_gradsvd_pt.json \
        --run-name loraxs_gradsvd_r${SEEDS[$i]} \
        --seed ${SEEDS[$i]} \
        --gpu ${GPUS[$i]} &
done
wait
```

W&B project: `test_adaptation`, group: `loraxs_gradsvd`.

**Result:** Performance was approximately the same as the original weight-SVD LoRA-XS baseline. Experiment stopped early.
